# CLI Runtime Types

Lody supports every CLI runtime published in the [ACP Registry](https://agentclientprotocol.com/get-started/registry).
The Agent picker combines registry entries with local ACP runtimes supported by Lody.

<img src="/_docs-assets/0304-more-cli.png" alt="More CLI" />

## Registry Runtimes

1. Open **Settings** -> **Agent Config**.
2. Click the add button.
3. Enter a name for the config.
4. Choose the CLI type you want from the registry-backed picker.
5. Add any required environment variables.
6. Click **Test** when the button is shown. This verifies that Lody can launch the runtime and read
   its capabilities, including supported models and runtime modes.
7. Save the config, then select it when creating a conversation.

Registry support means Lody can follow new ACP runtime entries as they are added upstream. The host
machine still needs the selected runtime's command, login, credentials, and dependencies installed
according to that runtime's own documentation.

## Oh My Pi (OMP)

Install and configure [Oh My Pi](https://github.com/can1357/oh-my-pi) on the machine running
Lody, and make sure `omp` is on its `PATH`. Choose **Oh My Pi (OMP)** from the registry-backed
Agent picker. Lody starts `omp acp` using your local installation and discovers its models and
modes over ACP. OMP owns its credentials and configuration; Lody does not download an OMP runtime.

Type `/` in the composer to select commands advertised by OMP over ACP, such as `/model`.
You can add arguments after selecting a command. Skill and extension commands appear when
OMP advertises them; commands available only in its terminal UI are not included. After changing
OMP's commands or extensions, refresh the Agent configuration's capabilities to reload the list.

Lody recognizes OMP's native `.omp/skills` project directory and `~/.omp/agent/skills` and
`~/.omp/agent/managed-skills` user directories, plus the shared `.agent/skills` and `.agents/skills`
roots at project and user level. These are default directory mappings; custom OMP profiles and
additional configured skill directories are not inferred.


Native GUI components, collaboration, steering, atomic commit plans, and management need
an OMP build with the corresponding ACP extensions. The pinned acceptance build and its
source patches are documented in the [OMP integration Spec](https://github.com/LodyAI/Lody/blob/main/specs/omp-native-acp.md).
Lody does not apply these patches to your local OMP installation.

## Custom ACP Agent

If your ACP-compatible agent is not listed in the picker, choose **Custom ACP** in
**Settings** -> **Agent Config**.

1. Enter a name for the config.
2. Set **CLI Type** to **Custom ACP**.
3. Fill **Launch command** with the command that starts the agent over stdio.
4. Add any required environment variables in the same Agent Config.
5. Click **Test** to verify that Lody can launch the agent and read its capabilities.
6. Save the config, then select it when creating a conversation.

Example launch command:

```bash
npx -y my-acp-agent --stdio
```

The launch command is parsed into a command plus arguments and spawned directly. Quotes are
supported for arguments with spaces, but shell features such as pipes, redirects, glob expansion,
and `$VARS` are not evaluated. Put environment variables in the Agent Config instead.

## Notes

- Some registry runtimes may still be experimental upstream.
- Before use, make sure required login credentials are already configured on the host where the
  Lody CLI runs.
- Local runtime types require their corresponding host command to be installed first.
- Model availability depends on the selected runtime, local installation status, and account
  permissions.
